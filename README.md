# Our Capital

Небольшое приложение на Vue 3 и Vite с публикацией в GitHub Pages.

## Локальный запуск

Нужен Node.js 24 (версия указана в `.nvmrc`).

```sh
npm ci
npm run dev
```

## Сборка

```sh
npm test
npm run build
npm run preview
```

Готовый сайт находится в `dist/`. Приложение использует базовый путь `/our-capital/`,
поэтому локальная версия также открывается по этому пути.

## Страницы

Посвящение открывается по `/our-capital/#/`, а кнопка «нажми лапкой» ведёт на
`/our-capital/#/finances`. Используется Vue Router с hash history, чтобы прямые
ссылки и обновление страницы работали в GitHub Pages без настройки сервера.

В разделе финансов на компьютере используется боковая навигация, а на телефоне —
нижняя панель. Основной маршрут открывает обзор капитала, распределение активов
и список счетов. Остальные разделы:

- `#/finances/securities` — ценные бумаги;
- `#/finances/securities/iis` — ИИС, отдельная вкладка внутри ценных бумаг;
- `#/finances/crypto` — крипта;
- `#/finances/savings` — наличные и накопления.

## Счета и аналитика

Интерфейс предназначен только для просмотра. Счета задаются в
`src/data/accounts.js`: идентификатор, название, категория, текущая стоимость
и валюта. После изменения данных нужен commit и push в `main` для публикации.
Обзор складывает счета в выбранной валюте; ценные бумаги и ИИС объединяются
в одну группу распределения без повторного учёта. Денежные счета RUB, BYN, USD
и EUR учитываются отдельно, без пересчёта между валютами.

Все посетители видят данные из опубликованной сборки. Форм редактирования нет;
`localStorage` для счетов не используется.

## Криптовалюта

Количество монет задаётся в `src/data/crypto.js`. Сейчас добавлена одна позиция:
1000 DOGE. Количество монет хранится отдельно от их денежной стоимости.

Курс загружается из публичного [Coinbase Exchange Rates API](https://docs.cdp.coinbase.com/coinbase-app/track-apis/exchange-rates)
при входе в финансовый раздел и обновляется раз в минуту, пока раздел открыт.
API не требует ключа; RUB, BYN, USD и EUR получаются одним запросом для DOGE.
Стоимость позиции равна количеству монет, умноженному на курс выбранной валюты;
до копеек округляется только итог. Эта оценка входит и в крипту, и в общий обзор.

Рядом с курсом указано местное время получения ответа. Если первый запрос не
удался, количество монет остаётся видно, а цена и общий итог показываются как
недоступные. При неудачном обновлении сохраняется последняя оценка с явной
отметкой времени. Повтор выполняется автоматически; доступна кнопка повтора.

`npm test` проверяет данные из кода, агрегацию, точность сумм, разделение валют,
ответы API и состояния недоступного курса. Сетевые запросы в тестах подменяются.
Эти проверки также выполняются в CI.

## Акции и ИИС

Позиции в `src/data/securities.js` задаются количеством акций в штуках. Категория
`securities` относится к обычному брокерскому счёту, `iis` — к ИИС. Сбербанк
учитывается как SBER, привилегированные акции — как SBERP. Цена покупки, дивиденды
и свободные деньги по этим позициям не заданы; показывается текущая оценка акций.

Котировки берутся из [MOEX ISS](https://www.moex.com/a2193), режим торгов TQBR.
При отсутствии последней сделки используется цена предыдущей сессии с её датой.
[Биржевые данные задержаны на 15 минут](https://www.moex.com/ru/data/).
Для USD, BYN и EUR цена в рублях пересчитывается по публичному курсу Coinbase RUB.
Четыре позиции оцениваются отдельно; в общем обзоре ценные бумаги и ИИС входят
в одну группу без повторного учёта. Количество акций не умножается на размер лота.

Во время сборки GitHub Actions формирует `dist/market/securities.json` через
`scripts/fetch-securities-snapshot.mjs`. Публикация также запускается каждые
15 минут для обновления снимка без коммитов данных. Браузер проверяет снимок
раз в минуту и принимает его только в пределах 30 минут с момента получения.
Если снимка нет или он просрочен, выполняется прямой запрос к Мосбирже.
Сохраняется исходное время получения, поэтому снимок не выдаётся за свежую сделку.

При недоступном источнике количества акций остаются видны, а неполная оценка
показывается как недоступная. Ошибка котировок не препятствует публикации сайта.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает приложение при каждом push в
`main`. Если GitHub Pages включён, workflow также публикует сайт. Пока Pages
выключен, сборка выполняется, а публикация пропускается. Workflow также можно
запустить вручную через вкладку Actions.

В настройках репозитория **Settings → Pages → Build and deployment → Source**
должен быть выбран **GitHub Actions**. Для Pages из приватного репозитория нужен
подходящий платный план GitHub; на GitHub Free репозиторий должен быть публичным.

Ожидаемый адрес после успешного деплоя:
<https://andrey-hauryk.github.io/our-capital/>.

При переименовании репозитория обновите `base` в `vite.config.js` и адреса сайта
в этом файле.

Документация: [Vite: GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages),
[GitHub: custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
